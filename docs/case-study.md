# ClientOps CRM Case Study

## 문제와 목표

고객 운영 담당자는 여러 고객의 상태와 마지막 접촉 시점을 빠르게 비교하면서, 한 고객의 정보와 상담 이력을 같은 흐름에서 갱신해야 합니다. 동시에 일반 직원에게 일상 업무 권한을 주되 영구 삭제는 관리자에게만 제한해야 합니다.

이 프로젝트의 목표는 화면 데모가 아니라 실제 인증·데이터·권한·오류 상태가 연결된 배포 가능한 CRM을 만드는 것이었습니다.

## 핵심 결정

### 고객 원장형 작업공간

검색 중심 상세, 상태 단계형 탐색, 고객 원장형 구조를 동일 데이터로 비교했습니다. 반복 업무에서 여러 고객을 스캔하고 정렬 상태를 유지하는 데 가장 적합한 원장형을 선택했습니다.

- 1440px: 고객명, 상태, 연락처, 수정 시각을 표의 안정된 축으로 비교
- 768px: 이메일처럼 우선순위가 낮은 열부터 제거
- 390px: 가로 스크롤 표를 폐기하고 핵심 필드 중심의 단일 행 목록으로 전환

### 네 겹의 삭제 권한 방어

STAFF 삭제는 버튼을 숨기는 것으로 끝내지 않았습니다. UI, 인증 DAL, Server Action 역할 검사, PostgreSQL RLS에서 각각 차단합니다. 고객 삭제는 되돌릴 수 없고 연결된 상담 기록도 함께 제거되므로 확인 대화상자에 대상 고객과 영향 범위를 명시했습니다.

### URL이 목록 상태의 원본

검색어 `q`, 상태 `status`, 페이지 `page`를 URL query로 관리합니다. 새로고침·공유·뒤로 가기에도 문맥이 유지되고, 상세에서 목록으로 돌아갈 때 동일한 결과와 페이지를 복원할 수 있습니다.

### 필터 전체 CSV

CSV는 화면의 현재 20건만 내보내지 않습니다. 목록과 같은 검색·필터·정렬을 사용해 전체 결과를 페이지 단위로 조회하고 RFC 4180 인용, CRLF, UTF-8 BOM, 한글 헤더를 적용합니다.

### append-only 상담 기록

상담 이력은 감사 가능한 시간 흐름으로 취급했습니다. 이번 범위에서는 수정·삭제 권한을 부여하지 않고 생성자와 UTC 시간을 함께 저장합니다.

## 상태와 오류 처리

- 로딩 화면은 최종 레이아웃의 주요 높이를 유지해 전환 흔들림을 줄입니다.
- 검색 결과 없음과 전체 데이터 없음은 서로 다른 복구 행동을 제공합니다.
- form mutation은 필드 오류, form 오류, 권한 오류를 구분하고 유효한 입력을 보존합니다.
- 저장 중에는 중복 제출을 차단하며 성공 후에는 결과와 다음 초점 위치가 분명합니다.

## 트레이드오프와 후속 과제

- 공유 STAFF 데모는 실제 mutation을 경험할 수 있지만 방문자 간 데이터가 섞일 수 있어 정기 초기화와 개인정보 입력 금지 안내가 필요합니다.
- 공개 ADMIN 계정으로 영구 삭제 흐름도 체험할 수 있게 하되, 로그인 전에 삭제 결과를 알리고 매일 샘플 데이터를 초기화합니다.
- 원격 Safari 실기기, 스크린리더 읽기 순서, 200% zoom은 별도 접근성 점검 대상으로 남깁니다.
- UI Foundation은 렌더 검증을 통과했지만 명시적 승인 전까지 `provisional` 상태입니다.
